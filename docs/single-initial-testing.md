# 单字首字母候选验证

本页对应0.4.15的单字候选源码增量，已纳入新完整离线包；
`dist/` 中既有0.4.14归档保持不变。行为合同见
`design/single-initial-candidates.md`。

## 当前源码结果

默认内置词库输入 `l`，第一页为：

`了、来、里、两、老、路、另、连、类`

“了”保留读音 `le`，“来”保留 `lai`；选择只消耗输入的一个 `l`，
不会把拼音自动补进raw，也不需要启用AI。
其他首字母同样按实际词库收录的规范单字读音补全，不是l的特例。
对于 `a` 等本身已有完整音节的输入，完整音节候选仍优先；
继续输入为 `lai`、退格恢复 `l`、Esc取消均保持原会话行为。
此增量没有将单字首字母边加入长输入词图，旧跨词混拼名次仍通过原断言。

新集成5项通过，覆盖单字母提交/规范学习、完整音节优先及多音同字去重、
继续输入/退格/取消、默认l首屏、overlay及学习快照隔离。
既有受影响集成40项通过、1项真实模型基线默认忽略：
ai_typo4、common_ranking7、mixed4、caret8、sentence17。
引擎单元20项通过，严格Clippy和格式检查通过。
旧混拼边界测试首次对单字母s沿用“仅整词与16个组合”计数失败，
已把新增独立单字候选纳入整词计数，再精确命中该单例通过；
未扩大词图beam或搜索预算，也未删除失败断言。

未执行新的真实用户宿主输入，旧包的验收不能证明这次新增功能已安装；
新包构建与核验结果见 `windows-validation.md`，安装复测见
`default-ai-compatibility-testing.md`。

用户再次报告实际AI纠错未生效，随后补充微信显示“应用范围受限”，
记事本显示“无纠正建议”。前者是范围门禁拒绝，后者的源码状态只在当前请求身份、
期限和原候选快照有效且后台返回空纠正结果时发布，不等同组件没有启动。
用户截图现已确认拼音为 `xuanzaizainalishangban`、第一候选“选在在哪里上班”，
状态为“AI 已检查：无纠正建议”，与既有固定正例相同；微信编号为S04（未声明）。

两个磁盘DLL摘要分别匹配对应已交付ZIP；旧0.4.12目录的helper已不存在。
这确认当前存在版本混用，不能把截图当成0.4.14现场验收；
模块路径及磁盘摘要仍不能证明已加载映像的全部内存字节，更不能据此断言唯一根因。
未自动退出记事本、改注册或替用户安装新包。
