# Flower 0.4.15：默认AI兼容与单字候选复测

## 默认行为

- 输入 `l`，默认词库首页含“了、来、里、两、老、路、另、连、类”。
  选择“来”消耗一个l，使用规范读音lai；不需要AI参与。
- “启用离线 AI 纠错”和“兼容未声明范围的应用”默认勾选。
  已有配置明确关闭AI的选择仍保留，可手动开启；兼容开关不会替你重置该选择。
- 微信等应用的S04（没有范围声明）及S08（空列表）在当前焦点/view归属、
  可编辑窗口检查通过后可使用AI，不要求自定义输入框冒充Edit。
  明确密码/PIN/私密、不支持类型和异常接口/数据仍拒绝，普通学习不扩权。
- 自定义私密框若没有范围声明和标准密码标记，可能无法识别；
  不接受此兼容取舍时，可关闭第二个选项，保存后切换输入法恢复严格路径。
  无网络服务、不读聊天历史或周边正文，只检查当前未提交的候选。

## 先确认实际运行版本

本次只读现场检查发现注册指向0.4.13，但打开的记事本加载0.4.12目录DLL，
该旧目录中helper已不存在；文件摘要分别与对应历史包匹配。
这确认版本混用，不证明它就是所有问题的唯一原因，也不把磁盘摘要当成内存映像证明。
没有自动退出用户软件、安装、注册、启用、改配置或删除旧目录。

升级前先保存工作、从当前用户停用Flower，正常退出用过Flower的记事本、
微信及其他宿主，再使用原卸载器卸载后安装新版。不覆盖正在使用的DLL，
不强杀软件、不手工删除未知残留或更改注册表。
启用过自启动的用户先正常关闭自启动，卸载不代其他用户清理。

0.4.15候选窗状态开头应显示 `Flower 0.4.15 · AI …`。
这来自当前DLL编译版本，不是设置程序标题或注册表猜测。
若仍没有此前缀或显示旧版本，不将其当作新版现场验收。

## 记事本固定纠错正例

在普通空白文本框中输入完整拼音：

```text
xuanzaizainalishangban
```

不要先按空格上屏；保持首页首选，光标在拼音末尾，停顿约5秒。
默认首项应仍是“选在在哪里上班”，目标是在其后出现
“现在在哪里上班 ✓ AI”。AI不抢占或自动替换第一项，也不回改已上屏正文；
需要选择带标记的第二项才会提交纠正文字，标记本身不提交、不学习。

随后测试 `xainzaizainalishangban`、`xinzaizainalishangban`、
`xiaanzaizainalishangban`，以及正确的 `xianzaizainalishangban`。
正确句没有建议属于预期；不保证任意错句都通过固定模型门槛。
个人排序导致首候选不同，需如实记录，不能当成同一个模型输入。

## 微信复测

使用新建空白聊天输入框或搜索框，先确认版本前缀，再使用上述固定公开句。
S04/S08不应仅因缺少Edit类而拒绝，但窗口身份、焦点、安全样式或其他错误仍可拒绝。
若仍受限，反馈完整版本、S编号及输入位置；不为演示在密码框或个人聊天历史中试验。

隔离测试通过不证明具体微信版本现场已通过。界面显示“无纠正建议”时，
记录完整拼音、首项和状态截图；“组件不可用”“超时”“范围受限”是不同阶段，
不要统称为模型没有启动。旧0.4.12诊断脚本不能直接用于新版。
