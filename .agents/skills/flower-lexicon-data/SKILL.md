# Flower 词库数据流程

先读当前 `design/input-and-installation.md`、`docs/distribution.md` 及 `data/pinyin/sources/manifest.json`。历史设计若已不存在，不依据旧摘要恢复。以实际阶段和共享行为契约为准，不因数据量扩大就宣称整句输入或用户学习已实现。

## 来源与许可

- 引入数据前读取实际来源、完整许可及合并说明。仓库总体标 MIT 不代表它混合的所有数据都只有 MIT；不要盲目将 pinyin-data/pinyin.txt、Rime 字典或可下载的专有词库一并导入。
- 固定发布版本/提交、原始 URL、文件 SHA-256、归属和许可正文。来源探针先放当前 Thread scratch；确认交付的快照放 `data/pinyin/sources/`，不执行上游脚本。
- 当前单字流水线使用固定 Unicode Unihan 读音字段及独立的 8105 转录检查集。保留两者的许可和归属，不冒充官方字表认证。完整原始 Unicode 快照供源码重建，不要求全部进入运行包。
- 字节锁定的来源、生成 TSV 和覆盖报告必须保留 Git 属性，防止 Windows 换行转换破坏 SHA。来源更换时同步清单、报告、许可、包白名单和实际消费者。

## 转换与覆盖

- `scripts/build_lexicon.py` 是离线入口，无网络依赖。`--check` 必须只校验而不覆盖文件；不支持的记录、来源哈希不符或许可缺失时失败关闭。
- 有声调拼音去声调；处理 Unicode 分解的 ü 时先保留其区分，再转换为 v，不能直接删所有组合符号后把 ü 错当 u。单字多音字取实际来源，不为词组制造读音笛卡尔积。
- 去重单位是 `(拼音, 文字)`，保留最高权重。先按文字分组去重，再做候选权重排序；仅按权重排序后相邻 dedup 会漏掉隔开的重复文字。
- 报告唯一字符、拼音—字映射及基线覆盖，不能把多音映射行数当成字符数。基线要通过实际 `Lexicon::lookup` 证明可达，另验大候选集所有页面及末项提交。
- 扩展平面字符需验证 UTF-16 编辑/读回；不能凭一个生僻字看似有读音就假定所选来源收录它。缺字、缺读音和 Windows 缺字形是不同问题，不编造映射来使测试通过。

## 引擎与性能

- 保留纯安全 Rust 边界；文件路径、网络和持久化策略不能进入引擎。内置词典进程内共享，session/router 快照不能深拷贝整部底表；自定义 TSV 不污染内置缓存。
- 初始化失败显式返回错误，不用空词典或退回演示库伪装成功。词库扩大不得暗中改变 Space/Enter、取消、候选票据或 TSF 编辑语义。
- 旧测试需要固定页数/短末页时使用明确的小 fixture，另保留生产大词库回归；不要放宽断言或截断真实候选来维持旧页数。
- `cargo run --release --example lexicon_probe` 是固定开发负载：冷加载、暖查询分位值、空 router 克隆。它不是桌面端到端按键时延，也不代表多宿主 RSS；按实际指标描述结果，不制造通用硬件保证。

## 分音、组合与本地学习

- 词级数据保留真实音节边界和独立许可；CC-CEDICT 派生数据及词频来源的归属不能被程序根许可证替代。默认核心与可选专名扩展分别验证数量、互斥和哈希，不自动启用扩展。
- 原始 ASCII 消耗范围不能从中文长度反推。显式分音符属于前一个消耗片段，逐一检查所有相关部分候选，避免选择后遗留前导引号。不要只验证第一个候选。
- 组合使用有限图搜索，精确单字候选仍完整。整数 log 近似需保留桶内频率，否则不同高频词可能仅因字典序倒排；不要为句子回归硬加整句词条。
- 学习事件不是持久化许可：试探、取消、无解原始输入、失败/过期编辑不得学习；只在成功提交及可靠非敏感 scope 下投递。未知 scope 失败关闭。关闭/清空要推进代次，防止其他宿主旧队列恢复记录。
- Windows 用户数据更新保持锁内重读、同步同目录临时文件和原子替换。慢持久化下短固定轮询可能饥饿，使用有界内核等待并验证总期限、跨进程与 abandoned 接管；不取消同步或吞掉失败。
- 不假定 share-delete 读取句柄一定允许目标被替换。合作读取与写入须协调；用受控短暂/永久占用、readonly 和原生 API 最小复现验证原子一致性。任何有限重试都保留旧文件，不删旧目标、不改权限、不换非原子兜底。
- DLL 内工作线程须 stop/join，并在 join 后才释放独立 DLL 存活计数；不要只依赖文本服务字段的默认析构次序。

## 字频与整词首字母

- 当前契约见 `design/input-and-installation.md`。单字使用固定 jieba 快照的精确文字频率，并在优先读音/其他基线读音/扩展读音三档内压缩排序；不要直接让文字总频率跨读音档，否则 `yi` 的“也”等次读音可能压过“一”。来源与许可损坏须失败关闭，coverage 和包校验同步；完整读音及分页候选不截断。
- 内置表不再叠加 MVP 演示权重，MVP 仅供小 fixture 和审计。已声明无解的测试输入可能因简拼获得真实候选（例如 `xyz`），用明确小词典测试无解契约，不删除候选或放宽断言。
- 简拼仅规范分音词条的每音节首个 ASCII 字母，至少两音节且每字一音节；预建共享索引，overlay/learning 后同步，按键不扫描全表。不猜连写演示词、不默认混拼或缩写组句。实际消耗用缩写 raw 长度，显示/学习保留 canonical reading。
- 0.4.1 增加用户已选择的项目日常词优先层，只分类真实既有规范词条，明确不是统计频率，不改 weight 也不造读音。分类、overlay、learning、initial 索引排序须同步；自定义 from_tsv fixture 仍按权重。优先层会影响高权重私词与日常词之间的顺序，更新测试时须保留私词可达、weight不变和快照隔离断言，不简单删除旧断言。
- 0.4.1 候选顺序为完整全拼→整词简拼→完整组合→部分前缀，防组合字串挤在真实简拼词之前。`nh/wm/sm/ky/zg/xx` 可用真实内置表检验常用词首屏，不给不存在的词补造读音。优先层与实际词频证据应分开报告，不冒充无偏质量基准。
- `tests/common_ranking.rs` 覆盖真实内置排序和简拼，`tests/pinyin_sentence.rs`、`tests/lexicon_quality.rs` 覆盖状态与快照一致性；原生 Context 回归可验证 NH 到“你好”的编辑路径，仍不证明实机激活。

## 最小充分验证

- 数据/转换：`python -m unittest scripts.test_lexicon -v`，`python scripts/build_lexicon.py --check`。
- 数据分发变化：覆盖 `scripts.test_package` 与 `scripts.test_installer` 的受影响边界，检查必需数据、许可、来源/覆盖一致性和白名单。ZIP 有多个 manifest.json 时，测试与工具必须精确定位顶层包清单，不能取第一个后缀匹配。
- 共享引擎变化：覆盖 engine、router、候选分页、相关原生 TSF 路径及严格 Clippy。修复后只补失败和受影响证据，不惯性反复全量重跑。
- 包构建与核验：沿用 `flower-windows-validation`。独立版本不覆盖旧制品；核验源 ZIP、包内哈希、字库许可、生成数据和 setup 关联。不自动安装、关闭宿主或覆盖已加载 DLL。
- 记录新执行、复用和未覆盖项。字库收录、查词、选择、TSF 写入、实际宿主及字体显示分别验收；未运行的 CI 和桌面测试保持未验收。
